# D — 공통 5지선다 검증·이후 시간 순서 실험

## 목표와 입력/출력

먼저 모든 모델을 같은 문제로 비교하는 평가기를 만듭니다. 입력은 제공 Train의 검증 분할, 정답 설명, 각 모델의 score 메서드입니다. 출력은 고정 후보 manifest와 순위 점수·Top-1·에피소드별 점수·실행 시간입니다. 학습이나 모델 예측을 사용해 정답 레이블을 새로 만들지 않습니다.

## 읽을 순서

1. `starterkit/dataset.py`: load_episodes, split_indices, write_splits.
2. `starterkit/evaluate.py`: 기존 평가는 정답/무작위 오답 두 개뿐이라는 점.
3. `starterkit/submission.py`: score와 predict 계약.
4. `starterkit/train.py`: splits.json·features.pt·checkpoint의 위치.
5. `docs/WORKFLOW.md`: 검증 manifest와 Git 공유 규칙.

## 첫 작업 — 아직 없는 코드

`starterkit/build_validation.py`, `starterkit/evaluate_ranking.py`를 새로 작성합니다. 현재 저장소에 이 두 명령이 구현되어 있는 것은 아닙니다.

1. A의 전체 Train split을 기다리는 동안 파일 로딩·평가 코드부터 작성합니다. 필요하면 기존 split_indices로 동일 전체 데이터·seed 2026·0.2 분할을 생성해 개발하고 A 결과와 ID를 비교합니다.
2. 확정 split을 `validation/splits.json`에 보관합니다. 원본 학습 코드는 이 파일을 직접 읽는 옵션이 없으므로 A/C의 실행 결과 split과 별도 대조해야 합니다.
3. 검증 에피소드마다 정답 설명 한 개와 **다른 validation 에피소드**의 설명 네 개를 고정 seed로 선택합니다. 자기 자신과 동일한 설명, 후보 간 중복 설명을 제외합니다. 서로 다른 설명이 부족하면 명확한 오류로 중단합니다.
4. 후보 순서를 고정 seed로 섞어 정답 위치가 고정되지 않게 합니다. 후보 ID는 문자열로 만들고 모델이 ID를 정답 단서로 쓰지 않도록 합니다.
5. manifest에는 입력 에피소드 ID, 후보 ID, 설명 소스 에피소드 ID, 정답 ID를 저장합니다. 원본 텍스트·이미지는 Git에 올리지 않습니다. 로컬 데이터 로더가 실제 설명을 읽습니다.
6. 평가기는 manifest를 읽고 각 모델에 **images와 choices만** 전달합니다. 정답 ID와 원본 소스 ID는 모델에 넘기지 않습니다.
7. 후보 점수 수·유한성·ID 누락/중복을 확인하고 내림차순 정렬합니다. 동점 처리는 입력 순서 등 일관된 규칙으로 정하고 기록합니다.

## 지표

정답 순위가 1/2/3/4/5위일 때 점수는 각각 1/0.5/0.25/0.125/0입니다. 모든 검증 에피소드의 점수 평균을 구합니다. 별도로 Top-1 정확도를 보고합니다.

아래는 구현할 함수의 수식 예시이며 데이터 생성이 아닙니다.

```python
rank_scores = {1: 1.0, 2: 0.5, 3: 0.25, 4: 0.125, 5: 0.0}
```

각 에피소드의 후보 ID·모델 점수·정답 순위와 실행 시간을 로컬 결과 파일에 저장합니다. 로딩 시간과 에피소드 처리 시간을 구분하고, CUDA timing은 완료 동기화 후 측정합니다.

## A/B/C가 쉽게 사용하게 만들기

평가기 실행 인자를 문서화합니다. 권장 항목은 data-dir, manifest, 모델 선택 또는 submission-dir, device, output입니다. **직접 구현하고 확인한 명령만** PR에 사용법으로 적습니다.

모델이 아직 없으면 기존 Submission으로 소규모 동작을 확인합니다. A의 전체 체크포인트가 준비되면 공통 검증으로 baseline 점수를 기록합니다. A/B/C에게 manifest와 평가 방법을 먼저 전달하고 PR을 합칩니다.

## 검증을 공유한 뒤 두 번째 작업

프레임 평균은 순서를 지웁니다. 별도 `starterkit/temporal_model.py`에서 시간 구간별 특징을 유지하는 작은 학습 모듈 등 순서 활용 방법을 실험할 수 있습니다. 단순히 순서 모듈을 추가했다고 행동 순서 구분 성능이 보장되지는 않습니다. 제공 Train의 실제 정답만 사용하고, C와 변경 파일·캐시 형태를 조율합니다.

현재 캐시는 프레임 평균 하나만 저장하므로 시간 구간/프레임 특징을 쓰려면 다시 추출하고 캐시 형식을 변경해야 합니다. 검증기 완성과 팀 공유가 먼저입니다.

## 한계와 전달

무작위 다른 영상 설명은 테스트의 유사 행동 오답보다 쉬울 수 있습니다. 같은 원본 영상·중복 이미지가 분할을 넘는지 가능한 메타데이터로 점검합니다. 검증 후보를 바꾸면 이전 모델도 같은 새 후보로 다시 평가합니다. public 리더보드를 보고 validation 정답/후보를 유리하게 조정하지 않습니다.
