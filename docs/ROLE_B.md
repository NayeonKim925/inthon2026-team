# B — SigLIP 대안 모델

## 목표와 입력/출력

허용 모델 `google/siglip-base-patch16-224`로 학습 없는 비교 기준을 만듭니다. 입력은 한 에피소드의 시간순 이미지들과 후보 설명입니다. 출력은 후보별 점수와 전체 ID 순위입니다. A의 baseline 학습 완료를 기다릴 필요가 없습니다.

## 읽을 순서

1. `starterkit/submission.py`: score와 predict의 입력·출력.
2. `starterkit/baseline_model.py`: 로컬 로딩·eval·추론 모드 사용 예.
3. `starterkit/export.py`, `package.py`: 현재 모델 전용 포장이라는 점 확인.
4. `docs/WORKFLOW.md`: 공통 모델 계약·검증·GPU 예약.

## 처음 구현할 것 — 아직 없는 코드

`starterkit/siglip_model.py`를 새로 만듭니다. 아래는 작업 목록이며 실행 가능한 SigLIP 구현이 이미 있는 것은 아닙니다.

1. 준비 단계에서 정확한 허용 모델과 processor/tokenizer를 로컬에 저장합니다.
2. 모델을 한 번 로드하고 eval·추론 모드로 고정합니다.
3. 프레임 이미지와 후보 텍스트를 각 인코더에 전달합니다.
4. 모델이 제공하는 이미지–텍스트 matching 점수를 사용해 프레임별 후보 점수를 구합니다. 별도 인코더 공간을 임의로 같은 공간이라고 가정하지 않습니다.
5. 첫 버전은 프레임 점수를 평균해 후보별 점수 하나로 만듭니다. 입력 전처리·정규화·텍스트 padding은 해당 모델 processor 설정을 따릅니다.
6. `score(images, choices)`와 점수 정렬 기반 `predict`를 제공합니다. 빈 이미지·점수 NaN·후보 ID 누락 등을 확인합니다.

학습 없이 기존 모델의 matching 능력을 쓰는 기준입니다. 평균 집계는 순서를 구분하지 못합니다. 성능 우위는 검증해야 하며 보장되지 않습니다.

## 시작 순서

1. 브랜치 `exp/siglip`으로 이동하고 새 파일에서 독립 개발합니다. 공통 submission.py는 A와 조율합니다.
2. 제공된 Train 한 에피소드로 코드 작동을 확인합니다. 다른 Train 설명을 후보로 사용할 수 있습니다. 외부 AI로 후보 문장을 새로 생성하지 않습니다.
3. GPU를 예약하고 한 에피소드의 처리 시간·VRAM·반환값을 확인합니다.
4. D의 manifest가 나오면 동일 후보·동일 에피소드로 점수를 계산합니다. D 완료 전에도 위 단계는 진행 가능합니다.
5. 프레임 수/선택과 점수 평균·최대 등을 한 요소씩 비교합니다. 샘플링은 순서를 유지하고 프레임 수를 기록합니다.
6. SigLIP 전용 export 또는 공통 export 확장을 구현해 필요한 모든 파일이 오프라인으로 읽히게 합니다. 기존 package의 DINOv2/MPNet 필수 목록도 대응해야 합니다.
